            How the workflow runs

            1. Create a project and fill in the repository, branch, milestone and the AUTOPILOT.md path.
            2. Add AUTOPILOT.md to the repository (copy the template below and ask ChatGPT to fill it in, or commit it yourself).
            3. Open your ChatGPT conversation with the GitHub repository connected.
            4. Click Start session. The first continuation prompt is prepared.
            5. Copy or Insert the prompt, read it, and press Send in ChatGPT yourself.
            6. When the response appears complete you get a notification. Read the reply, then Mark cycle reviewed and pick what ChatGPT reported: continue, milestone met, or blocked.
            7. The next prompt is prepared. Repeat until the milestone is met, a blocker needs you, the cycle limit is reached, or you stop.

            What the extension can and cannot know

            • Observed: whether the ChatGPT page shows a stop control, a streaming marker, an error or usage-limit notice, and whether a new assistant message appeared. If the page does not expose this, the status is Unknown.
            • Reported: anything about the repository or AUTOPILOT.md. The extension has no access to GitHub and does not read ChatGPT's replies; it only records what you choose when reviewing.
            • A finished response is not proof that work succeeded, and a stopped response is not proof that the milestone is met.
            • On a usage-limit message, monitoring pauses. Nothing is reloaded or resent.
